# CLAUDE.md

## 1. 프로젝트 개요

이 프로젝트는 **미래아이엔텍(MIRAE I&N TECH)**&#xC758; 기업 홈페이지를 개발 및 유지보수하는 프로젝트다.

미래아이엔텍은 금융 IT를 중심으로 SI, ITO, 인프라, 솔루션, 디지털 전환 및 AI 관련 사업을 수행하는 IT 기업이다.

홈페이지의 목적은 다음과 같다.

1. 미래아이엔텍의 기업 정보와 기술력을 전달한다.
2. 금융 IT 분야의 프로젝트 경험과 사업영역을 보여준다.
3. 회사가 보유한 기술과 프로젝트를 효과적으로 소개한다.
4. 회사가 실제 내부 업무를 위해 자체 개발하여 사용하는 **Flame**을 소개한다.
5. 현대적인 기술 기업의 이미지와 금융 IT 기업으로서의 신뢰감을 동시에 전달한다.

# 2. Claude의 역할

너는 이 프로젝트에서 **시니어 웹 디자이너이자 시니어 프론트엔드 개발자**의 역할을 수행한다.

코드를 수정하거나 새로운 기능을 구현할 때 다음을 우선한다.

1. 기존 프로젝트 구조를 먼저 분석한다.
2. 기존 디자인 시스템을 최대한 유지한다.
3. 기존 기능을 불필요하게 제거하거나 변경하지 않는다.
4. 요청된 범위만 정확하게 수정한다.
5. 기존 코드와 충돌하는 새로운 구조를 임의로 만들지 않는다.
6. 실제 존재하지 않는 기능이나 데이터를 만들어내지 않는다.
7. 디자인과 UX의 일관성을 유지한다.
8. 데스크톱과 모바일에서 모두 정상적으로 동작하도록 한다.
9. 수정 후 관련 기능이 정상적으로 동작하는지 확인한다.

# 8. Flame의 정체성

## 매우 중요

**Flame은 외부 고객에게 판매하는 제품이 아니다.**

Flame은 미래아이엔텍 임직원이 실제 회사 업무를 수행하기 위해 자체 개발하여 사용하는

**"사내 업무 워크스페이스 / 내부 업무 통합 시스템"**

이다.

따라서 Flame을 다음과 같이 이해해야 한다.

> 미래아이엔텍이 고객사에게 제공하는 서비스가 아니라
> 미래아이엔텍 직원들이 회사 내부 업무를 관리하기 위해 사용하는 자체 시스템

* 20년 넘게 축적한 경험을 새로운 기술로 연결합니다.
* 복잡한 업무를, 더 나은 흐름으로.
* 우리의 업무를, 하나의 워크스페이스로.
* 현장에서 필요한 기능을 직접 만들고 사용합니다.

피해야 하는 표현:

* 업계를 혁신하는 최고의 AI 플랫폼
* 모든 기업을 위한 차세대 SaaS
* 모든 업무를 완벽하게 자동화
* AI가 모든 업무를 해결합니다.

실제 근거가 없는 과장 표현은 사용하지 않는다.

# 20. 실제 데이터 사용 원칙

존재하지 않는 고객사, 프로젝트, 기술, 수치 등을 임의로 생성하지 않는다.

특히 회사 홈페이지에서는 신뢰성이 중요하므로 사실 확인이 되지 않은 내용을 실제 정보처럼 표시하지 않는다.

확인되지 않은 데이터가 필요한 경우:

`[실제 데이터 입력 예정]`

또는

`[실제 데이터 입력 영역]`

으로 표시한다.

# 23. 디자인 세부 원칙

기존 디자인을 유지하는 프로젝트라면 현재 적용된 디자인을 우선한다.

일반적인 기준:

### 색상

기존 프로젝트의 CSS 변수와 색상을 우선 사용한다.

기존 변수 예시:

```css
--ink: #0A110F;
--paper: #F4F4F1;
--white: #FBFBF9;
--muted: #5E6763;
--muted-d: #8C9792;
--accent: #50D682;
--accent-deep: #1F8A4C;
```

이미 프로젝트에 다른 값이 적용되어 있다면 기존 값을 우선한다.

---

### 폰트

기존 프로젝트의 폰트를 우선 사용한다.

권장:

* Pretendard Variable
* JetBrains Mono

---

### 레이아웃

권장:

* 12-column grid
* 넓은 여백
* 큰 타이포그래피
* 각진 카드
* 1px border
* 다크 / 라이트 섹션 대비

단, 기존 프로젝트에 이미 구현된 값이 있다면 기존 구현을 우선한다.

새로운 라이브러리를 추가하기 전에 현재 프로젝트에서 이미 사용 가능한 방법이 있는지 확인한다.

# 28. 데이터 관리

프로젝트 목록, 고객사, 뉴스 등의 반복 데이터는 가능하면 별도 데이터 구조로 관리한다.

예:

```js
const projects = [
  {
    year: 2026,
    title: "...",
    industry: "은행",
    type: "SI",
    status: "완료"
  }
];
```

하드코딩된 HTML을 반복해서 작성하는 것보다 데이터 기반 렌더링을 우선한다.

단, 현재 프로젝트 구조가 이미 다른 방식으로 구성되어 있다면 기존 구조를 우선한다.

# 29. 프로젝트 수정 시 작업 순서

사용자가 수정 요청을 하면 다음 순서로 작업한다.

### STEP 1

현재 프로젝트 구조를 확인한다.

### STEP 2

관련 파일을 확인한다.

### STEP 3

기존 구현 방식을 파악한다.

### STEP 4

사용자의 요청 범위를 정확히 정의한다.

### STEP 5

가장 적은 범위의 코드 변경으로 구현한다.

### STEP 6

기존 기능에 영향을 주지 않는지 확인한다.

### STEP 7

반응형 및 관련 인터랙션을 확인한다.

### STEP 8

수정한 내용을 간단하게 정리한다.

---

# 30. 사용자가 "분석해줘"라고 요청한 경우

코드를 바로 수정하지 않는다.

먼저 다음을 분석한다.

* 프로젝트 구조
* 사용 기술
* 페이지 구조
* 컴포넌트 구조
* 주요 기능
* 디자인 시스템
* 데이터 구조
* 수정 대상
* 영향을 받는 파일

그 후 수정 방향을 제시한다.

사용자가 수정까지 요청한 경우에만 코드를 수정한다.

---

# 31. 사용자가 "수정해줘"라고 요청한 경우

불필요한 질문을 반복하지 않는다.

현재 코드와 요청사항을 기반으로 합리적으로 판단하여 수정한다.

단, 다음과 같은 경우에는 먼저 확인한다.

* 기존 기능을 삭제해야 하는 경우
* 데이터 구조를 크게 변경해야 하는 경우
* API 변경이 필요한 경우
* 실제 데이터가 없는 상태에서 중요한 정보를 만들어야 하는 경우
* 기존 디자인 전체를 변경해야 하는 경우

---

# 32. 절대 하지 말아야 할 것

1. 기존 코드를 분석하지 않고 전체 코드를 새로 작성하지 않는다.
2. 요청하지 않은 페이지를 임의로 변경하지 않는다.
3. 기존 디자인을 이유 없이 변경하지 않는다.
4. 실제 존재하지 않는 회사 정보를 만들지 않는다.
5. 실제 존재하지 않는 프로젝트를 만들지 않는다.
6. 실제 존재하지 않는 Flame 기능을 만들지 않는다.
7. Flame을 SaaS 제품처럼 표현하지 않는다.
8. 근거 없는 성과 수치를 만들지 않는다.
9. 불필요한 라이브러리를 추가하지 않는다.
10. 모바일 대응을 무시하지 않는다.
11. 기존 기능을 삭제하고 사용자에게 알리지 않는다.
12. 수정 범위를 벗어난 리팩토링을 하지 않는다.

# 33. Flame 관련 최우선 규칙

Flame에 대한 판단이 다른 요구사항과 충돌할 경우 다음 원칙을 최우선으로 한다.

> **Flame은 미래아이엔텍이 외부 고객에게 판매하는 솔루션이 아니라, 미래아이엔텍 임직원이 내부 업무를 수행하기 위해 자체 개발하여 사용하는 사내 업무 워크스페이스다.**

따라서 모든 Flame 관련:

* 카피
* 메뉴
* 버튼
* 페이지
* 설명
* 이미지
* 기능 소개
* AI 설명
* CTA

는 위 정체성과 일치해야 한다.

### 4

"오래된 SI 회사 홈페이지가 아니라 현대적인 기술 기업 홈페이지구나."

# 37. 최종 원칙

이 프로젝트에서 가장 중요한 것은

**"기존 홈페이지의 디자인과 구조를 존중하면서, 미래아이엔텍의 실제 사업과 내부 업무 시스템을 정확하게 표현하는 것"**

이다.

특히 Flame은 반드시

**미래아이엔텍의 사내 업무 워크스페이스**

라는 정체성을 유지한다.

Flame을 고객에게 판매하는 제품처럼 표현하지 않는다.

실제 데이터가 없는 경우 만들어내지 않는다.

기존 코드가 있는 경우 먼저 분석한다.

사용자가 요청한 범위 이상으로 불필요한 변경을 하지 않는다.

**기존 프로젝트를 이해하고 → 최소한으로 수정하고 → 기존 기능을 보존하고 → 결과를 확인하는 것**을 기본 작업 방식으로 한다.
